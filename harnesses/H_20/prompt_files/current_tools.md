# BlendCUA v2 — Current Tools Reference

This file is the part of the toolkit that **every** build needs: setting the
view, picking geometry, and applying a transform. It is not the whole toolkit —
see *Finding a tool* below for the rest, which is a `read` away rather than in
this prompt.

All tools live under `Tool_scripts/Tools_code/`. The TOOLS_CODE path is added to
`sys.path` by `use()` at the top of every action file, so all imports below work
as written once you have called `use(...)`.

## How every action file is structured

```python
import sys
TOOLS_CODE = r"C:\Users\render\Joshi\Blenduse\BlendCuavb_run\Tool_scripts\Tools_code"
if TOOLS_CODE not in sys.path:
    sys.path.insert(0, TOOLS_CODE)
```

`use()` must come first. `shot()` must come last. Nothing renders or persists
without `shot()` — the runner will timeout waiting for `last_step.json`.

# Finding a tool

Parts 1–3 below are here in full because you need them on nearly every action.
Everything else is one `bash` call away, and **a tool you have not been told
about is the most expensive kind of mistake** — you will hand-roll fifty lines
of bmesh to do something one call already does, and do it worse.

So before writing anything non-obvious, check whether it already exists:

```bash
python Tool_scripts/tool_help.py --search crack     # find it by what it does
python Tool_scripts/tool_help.py apply_chain        # its FULL docstring
python Tool_scripts/tool_help.py --module handle    # everything in one module
```

**Read the full docstring before the first time you call any tool.** The
one-liners in the map below tell you a tool exists; they are not enough to call
it correctly, and guessing an argument you could have read is the single
cheapest error to avoid here.

## Generic folded surfaces with openings

Use `fenestrated_lamina` when a broad thin part is inspected in Solid shading or
when its openings must remain physical geometry. Call
`build_fenestrated_lamina(...)` with caller-owned outer/opening contours, a
fold/midrib field, an attachment anchor, and per-instance profile parameters;
it returns one connected non-rectangular lamina with real opening boundaries,
optional boundary side treatment, and a construction audit. The image texture
may supply colour and fine detail, but an alpha-only rectangular carrier is not
the judged silhouette. Read the full module docstrings in
`Tool_scripts/Tools_ref/INDEX.md` before calling it, and pair this trigger with
`Skills/Planner/Objects/flat-objects.md`.

# Part 1 — Viewport Tools

These control what the camera sees. Use them to set up a clean view before
rendering overlays or taking screenshots. The quality of every overlay depends
entirely on having a good view angle first.

## Summary table

| # | Tool | One-liner call | Notes |
|---|------|----------------|-------|
| V1 | Get viewport handles | `area, region, rv3d = get_viewport()` | Always call first; flushes `rv3d.update()` |
| V2 | Ortho snap (manual zoom) | `setup_axis_ortho_view(area, region, rv3d, axis='FRONT', zoom_out=1.2)` | Fits all scene objects, then adjusts zoom |
| V3 | Ortho snap (auto-fit objects) | `fit_objects_ortho_view(area, region, rv3d, axis='FRONT', names='all', ratio=80)` | **Preferred.** Centers + zooms to named objects |

## ⚠️ Screen coordinates — read this before picking anything off a screenshot

**The screenshot you are shown is not in Blender's pixel space.** Renders are
made at **2× the 3D region**, then capped at **1440×1080** after the overlays
are drawn — while the live region is whatever size the Blender window happens
to be (commonly ~797×598). So the image is roughly 1.8× the region here, but
the factor depends on the window and you must never assume it. On top of that,
image `y` grows **downward** from the top-left, and Blender's region `y` grows
**upward** from the bottom-left.

So a pixel you measure on the image is wrong twice if you hand it to Blender:

```python
# ✘ WRONG — silently unprojects to a completely different world point.
world = view3d_utils.region_2d_to_location_3d(region, rv3d, (570, 405), (0,0,0))
```

This exact mistake has cost multiple real runs several wasted actions: the
correct spot was picked by eye, the object then jumped far off target, and the
next 2–3 actions went on diagnosing and undoing it.

**Always express a screen pick as normalised 0–1 top-left coords** — which is
already what every overlay in this toolkit labels its dots with — and convert
with V9:

```python
# ✔ RIGHT
from lib.view import unproject_norm
world = unproject_norm(0.557, 0.527, region, rv3d)
```

If you did measure a raw pixel (e.g. from a PIL scan of the delivered PNG),
divide by **that PNG's own** width/height first — never by `region.width` /
`region.height`:

```python
W, H = Image.open(shot_path).size          # the image's OWN size — always read it
world = unproject_norm(px / W, py / H, region, rv3d)
```

## V1 — Get viewport handles

Every view or overlay call needs `area`, `region`, and `rv3d`. Get them once at
the top of any action that touches the view.

```python
area, region, rv3d = get_viewport()
```

## V2 — Ortho snap to a named axis (manual zoom control)

Snaps to one of the six canonical ortho views, runs `view_all` to fit the whole
scene, then applies a zoom multiplier.

`zoom_out > 1.0` zooms out (more headroom), `< 1.0` zooms in, `= 1.0` leaves
the `view_all` zoom unchanged.

```python
area, region, rv3d = get_viewport()
setup_axis_ortho_view(area, region, rv3d, axis='RIGHT', zoom_out=1.3)
# axis options (Blender Z-up, Y-forward convention):
#   'TOP'    — camera at +Z, looking down  (-Z); see XY plane (bird's eye)
#   'BOTTOM' — camera at -Z, looking up    (+Z)
#   'FRONT'  — camera at +Y, looking back  (-Y); see XZ plane (X right, Z up)
#   'BACK'   — camera at -Y, looking fwd   (+Y)
#   'RIGHT'  — camera at +X, looking left  (-X); see YZ plane (Y into screen, Z up)
#   'LEFT'   — camera at -X, looking right (+X)
```

**Do NOT call `focus_selected()` after this.** `focus_selected` overwrites
`view_distance` and cancels the `zoom_out` you set.

## V3 — Auto-fit named objects to ortho view (preferred)

Snaps to an ortho axis, then centers and zooms the view so that the bounding box
of the named objects fills exactly `ratio`% of the viewport in its larger
dimension. This removes the guesswork from zoom entirely.

`ratio=80` → object fills 80% of screen (safe margins on all sides).
`ratio=110` → object slightly overflows the frame (tight crop, zoom in past edges).

```python
area, region, rv3d = get_viewport()

# Fit all mesh objects from the front
fit_objects_ortho_view(area, region, rv3d, axis='FRONT', names='all', ratio=80)

# Fit only the Leg object from the right side
fit_objects_ortho_view(area, region, rv3d, axis='RIGHT', names='Leg', ratio=85)

# Fit multiple named objects from the top
fit_objects_ortho_view(area, region, rv3d, axis='TOP', names=['Leg', 'Base'], ratio=80)
```

`names` accepts: `'all'` (every MESH in the scene) | a single name string | a
list of name strings. Unknown names are silently skipped.

## V4 — Inline zoom

Quick relative zoom without snapping the view axis. Useful for nudging after a
view is already set up.

```python
_, _, rv3d = get_viewport()
rv3d.view_distance *= 0.7    # zoom in (objects appear larger)
rv3d.update()

_, _, rv3d = get_viewport()
rv3d.view_distance /= 0.7    # zoom back out
rv3d.update()
```

## V5 — Focus on selection

Centers and fits the viewport on whatever is currently selected. Equivalent to
pressing Numpad `.` in Blender.

```python
area, region, rv3d = get_viewport()
focus_selected(area, region, rv3d)
```

Use this when you've just selected a specific face or loop and want to zoom in on
it before rendering an overlay.

## V6 — Pan to a normalised screen point

Pans the view so that the given screen-space coordinate becomes the new viewport
center. Coordinates are 0–1, PIL convention (top-left origin, y grows downward).

```python
area, region, rv3d = get_viewport()
pan_to_norm(0.5, 0.3, region, rv3d)   # shift view so top-third is centered
```

## V7 — Viewport dot-drag overlay

Draws a labeled grid of dots across the full viewport. Use it to pick a coarse
target location in a large scene before committing to a more precise overlay.

```python
from perceive import viewport_drag_dots
data = viewport_drag_dots(rows=8, cols=10)
shot("dot grid rendered — pick (r, c) from screenshot")
# Next action: read (r, c) from the PNG and use the world coords in data
```

## V8 — Viewpoint quality

Returns 1.0 when the view axis is perpendicular to the given world axis, 0.0
when edge-on. Use this to confirm a view is suitable before rendering a ruler —
rulers collapse to a point when the value is below ~0.3.

```python
area, region, rv3d = get_viewport()
q = viewpoint_quality(axis_world=Vector((0, 0, 1)), rv3d=rv3d)
# q ≈ 1.0 → good for Z-axis rulers; q < 0.3 → rotate view first
```

## V9 — Screen pick → world point (`unproject_norm`)

Turns a point you identified visually on a screenshot into a world-space
`Vector`, handling the image→region rescale and the Y flip for you. See the
warning box above for why doing this by hand is a trap.

`depth` is the world point whose depth-plane the pick lands on (perpendicular
to the view direction). Default is the world origin, i.e. the `z = 0` modelling
plane when you are in TOP ortho.

```python
area, region, rv3d = get_viewport()

# Centre a reference image empty on the torso spotted at (0.557, 0.527):
torso = unproject_norm(0.557, 0.527, region, rv3d)
ref.location = (-torso.x, -torso.y, ref.location.z)

# Pick on the plane through the current face instead of z = 0:
tip = unproject_norm(0.62, 0.31, region, rv3d, depth=face_center_world)
```

It raises `ValueError` if you pass anything outside 0–1 — that guard exists
specifically to catch screenshot pixels being passed by mistake.

## V10 — World point → screen pick (`project_to_norm`)

The inverse. Cheapest possible self-check: after a move, project the world
point you were aiming at and confirm it comes back at the normalised coords you
originally picked, instead of burning an action on another screenshot.

```python
xn, yn = project_to_norm((0.0, 0.0, 0.0), region, rv3d)
shot(f"world origin now sits at normalised ({xn:.3f}, {yn:.3f}) — expected the torso pick")
```


## P1 — Model outline on the reference photo (`silhouette_vs_reference`)

```python
from perceive import silhouette_vs_reference
res = silhouette_vs_reference("BatBody")              # or ["BatBody", "BatWing"]
for st in res["stations"]:
    print(st["u"], st["half_width"])
```

Draws the evaluated mesh's silhouette (modifiers applied, so a Mirror shows up)
straight onto the reference photo, cropped around the mesh, and returns the
half-width at each sampled station in the photo's own coordinates.

**Use this, not a viewport screenshot, whenever the question is "does my shape
match the reference?"** A screenshot shows the model composited over the photo
with solid shading covering it exactly where the comparison matters: you can
see that the mesh is roughly over the subject, not that it is twice too wide.
The outline leaves the photo visible on both sides of every edge.

The returned `stations` are numbers, so you can compare them against a pixel
scan of the photo in `bash` instead of eyeballing. That is the difference
between "looks about right" and knowing.

`axis='Y'` (default) samples slices along world Y — the head-tail direction in
this build. `samples` controls how fine the sampling is.

## S5 — enter_edit: reset to a clean edit context (call this first)

Every action file that operates on a specific object should start with this.
It handles any prior Blender state: wrong mode, wrong active object, leftover
selection from the previous action, or a mid-operation crash that left the
session in an unknown state.

```python
from lib.mesh import enter_edit

obj = enter_edit("Base")             # exits any mode, selects Base, enters EDIT, selects all
bm  = bmesh.from_edit_mesh(obj.data)
mw  = obj.matrix_world
```

Pass `select_all=False` when the action will immediately make its own selection
rather than operating on the whole mesh:

```python
obj = enter_edit("Cushion", select_all=False)
bm  = bmesh.from_edit_mesh(obj.data)
# ... now make a specific selection before the overlay or op ...
```

## S1 — Face grid picker (coarse, position-based)

Draws a numbered dot grid over the viewport, then raycasts a chosen dot to
find the face beneath it. Best when you're picking faces by screen position
(e.g., "the face in the upper-left quadrant") rather than by identity.

Both calls must be in separate actions — the apply call reads the JSON file
the render call wrote.

```python
# Action N: render the grid
area, region, rv3d = get_viewport()
fit_objects_ortho_view(area, region, rv3d, axis='FRONT', names='Cushion', ratio=85)
face_grid(tl_norm=(0.2, 0.2), br_norm=(0.8, 0.8), rows=12, cols=12, labels=True)
shot("face grid rendered — read screenshot, pick (row, col)")

# Action N+1: apply — set ROW, COL from what you read in the PNG
ROW, COL = 5, 6
face_idx = face_at_grid(row=ROW, col=COL)
bm.faces.ensure_lookup_table()
bm.faces[face_idx].select = True
bmesh.update_edit_mesh(obj.data)
shot("face at grid (5, 6) selected")
```

## S2 — Labelled face window (fine, identity-based)

Labels each visible face center with a short tag (f1, f2, …) and a colored dot.
Better than the grid when you need to pick a specific face by identity — for
example, the top cap of a cylinder when there are many faces nearby.

```python
# Action N: render labels over the area of interest
area, region, rv3d = get_viewport()
fit_objects_ortho_view(area, region, rv3d, axis='TOP', names='Cushion', ratio=90)
face_map(tl_norm=(0.2, 0.15), br_norm=(0.8, 0.85))
shot("face labels rendered — read _fmap.png, note label")

# Action N+1: select the labelled face
LABEL = "f3"   # read from screenshot
face_idx = face_at_label(LABEL)
bm.faces.ensure_lookup_table()
deselect_all(bm)
bm.faces[face_idx].select = True
bmesh.update_edit_mesh(obj.data)
shot(f"face {LABEL} selected")
```

## S3 — Labelled vertex window

Renders a vertex map overlay: every vertex in the crop window gets a label and
its world position is written to a JSON sidecar. Use when you need to identify
a specific vertex by world position (e.g., to set a pivot, cursor, or move target).

```python
from lib.util import run_overlay
import json, os

area, region, rv3d = get_viewport()
fit_objects_ortho_view(area, region, rv3d, axis='FRONT', names='Leg', ratio=85)
shot("view set for vertex map")

# The overlay runs as a subprocess and writes a JSON sidecar next to the PNG
screenshot_png = "mem/bar_stool_run_003/steps/step_005/screenshots/action_01.png"
projection_json = screenshot_png.replace(".png", "_proj.json")
run_overlay("overlays/vertex_map.py", screenshot_png, projection_json,
            tl_norm=(0.2, 0.1), br_norm=(0.8, 0.9))

with open(projection_json) as f:
    vdata = json.load(f)
# vdata["vertices"] = [{label, px: {x,y}, world: [x,y,z]}, ...]
```

Same pattern as vertex map but for edges. Each visible edge in the crop window
gets a label and its midpoint + endpoint world positions in JSON.

```python
run_overlay("overlays/edge_map.py", screenshot_png, projection_json,
```

## S5 — Select by screen rectangle

Selects all elements of the given mode whose screen projection falls inside
the normalised bounding box. Good for "select everything in the top half of
the view" style operations without needing individual labels.

Must be in EDIT mode. The selection is immediate — no second action needed.

```python
bpy.ops.object.mode_set(mode='EDIT')
n = select_in_region(tl_norm=(0.1, 0.1), br_norm=(0.9, 0.5), mode='EDGE')
shot(f"selected {n} edges in top half of view")
# mode options: 'VERT' | 'EDGE' | 'FACE'
```

## S6 — Select verts by predicate

Filters BMVerts by an arbitrary Python condition. The predicate receives a
`BMVert` with `.co` in local space; use `mw @ v.co` for world space.

```python
bm = bmesh.from_edit_mesh(obj.data)
mw = obj.matrix_world
deselect_all(bm)
select_verts_where(bm, predicate=lambda v: (mw @ v.co).z > 0.5, mw=mw)
bmesh.update_edit_mesh(obj.data)
shot("all verts above Z=0.5 selected")
```

## S7 — Select verts at specific world-Z levels

Selects vertices that sit at exact Z heights in world space (tolerance ±1e-3).
Ideal for ring-selection on parametric objects like cylinders, where all verts
in a loop share the same Z.

```python
from lib.mesh import z_levels, select_verts_at_z

bm  = bmesh.from_edit_mesh(obj.data)
mw  = obj.matrix_world
all_zs = z_levels(bm, mw)          # sorted list of all unique Z heights
top_z  = max(all_zs)               # topmost ring

deselect_all(bm)
select_verts_at_z(bm, mw, z_levels=[top_z])
bmesh.update_edit_mesh(obj.data)
shot(f"top ring at Z={top_z:.4f} selected")
```

## S8–S11 — Landmarks (durable named references)

Landmarks are Blender vertex groups stored as `bc_<name>`. They survive topology
ops (extrude, subdivide, bevel) but are destroyed by vert deletion.

**Critical rule:** `tag()` toggles between OBJECT and EDIT mode internally.
Extract any numeric values you need from BMesh elements **before** calling
`tag()`, because the BMesh reference is invalidated when mode switches.

```python
from landmarks import tag, resolve, select as lm_select, select_edges_among

# Tag the currently selected loop
bm = bmesh.from_edit_mesh(obj.data)
mw = obj.matrix_world
# Capture values BEFORE tag()
top_z = max((mw @ v.co).z for v in bm.verts if v.select)
tag("cushion_top_ring", "top loop of cushion disc")

# Later, in a different action, re-select it:
bpy.ops.object.mode_set(mode='EDIT')
lm_select("cushion_top_ring")   # deselects all, re-selects the group

# Or resolve to BMVerts (re-fetch bm first after any bpy.ops call):
bm = bmesh.from_edit_mesh(obj.data)
verts = resolve("cushion_top_ring")

# Or select only the edges whose both endpoints are in the group:
select_edges_among(["cushion_top_ring"], bm, exclusive=True)
bmesh.update_edit_mesh(obj.data)
```

## S12–S13 — Reading tick/label values from overlay JSON

All overlay calls return a `data` dict. Use `pick()` and `between_ticks()` to
extract the numeric value for a label you read from the overlay PNG.

```python
from perceive import extrude_ruler, pick, between_ticks

data = extrude_ruler(axis=(0, 0, 1), kind='screen', step=40)
shot("ruler rendered")

# Next action — after reading the PNG:
t = pick(data, "e3")["t"]            # world-space distance for tick e3
t_mid = between_ticks(data, "e2", "e3", frac=0.5)  # halfway between e2 and e3
```

# Part 3 — Operation Tools

These apply mesh transforms. **Every operation that sets a spatial value must
be preceded by its matching overlay in the previous action.** The overlay shows
you the candidate values; the apply action uses the value you read.

The two-action pattern is mandatory:
1. **Render action** — call the overlay function, call `shot()`, stop.
2. **Apply action** — read the value from the PNG, hardcode it, apply the op.

Never pre-write the apply action before running the render action.

## Summary table

| # | Operation | Render call | Apply call |
|---|-----------|-------------|------------|
| O1 | Extrude along axis | `extrude_ruler(axis, kind, step)` | `bpy.ops.mesh.extrude_region_move(...)` |
| O2 | Scale verts / faces | `scale_overlay(axis_mask, factors)` | `bpy.ops.transform.resize(value=(f,f,1))` |
| O3 | Inset face | `inset_overlay(px_step)` | `bpy.ops.mesh.inset(thickness=t)` |
| O4 | Loop cut direction | `loopcut_dirs(seed_loop_indices)` | `bmesh.ops.subdivide_edges(...)` |
| O5 | Grab to 2D grid point | `grab_preview(plane_axes, n_dots, px_step)` | `grab_at(i, j)` |
| O6 | Grab along single axis | `grab_line_preview(axis, kind, step)` | `bpy.ops.transform.translate(value=...)` |
| O7 | Rotate single axis | `rotate_preview(axis, reference_pt, pivot)` | `bpy.ops.transform.rotate(value=..., orient_axis=...)` |
| O8 | Rotate trackball | `rotate_trackball(reference_pt, pivot, n_dots, deg_step)` | `trackball_at(i, j)` |
| O9 | Mirror modifier | direct: `obj.modifiers.new(...)` | (no overlay needed) |
| O10 | Bevel modifier | direct: `obj.modifiers.new(...)` | (no overlay needed) |
| O11 | Subsurf modifier | direct: `obj.modifiers.new(...)` | (no overlay needed) |
| O12 | Handle arc segment | `prepare_segment(angle_deg, grab_steps)` | `apply_grab(label, row, col)` |
| O13 | Reference backdrop | `load_reference(path, name, size, location)` | (one-shot; no apply step) |

## O1 — Extrude along an axis

Renders a ruler of tick marks showing how far an extrude would move along the
given axis. Ticks are labeled `e1`, `e2`, … Read the PNG, pick the label closest
to your target distance, then hardcode `t` in the apply action.

`kind='screen'` spaces ticks at fixed pixel intervals (best when zoomed out).
`kind='world'` spaces them at fixed metre intervals (best when you know the target size).

```python
# Action N: render ruler
from perceive import extrude_ruler, pick
area, region, rv3d = get_viewport()
fit_objects_ortho_view(area, region, rv3d, axis='FRONT', names='Leg', ratio=85)
bpy.ops.object.mode_set(mode='EDIT')
# select the top face first
data = extrude_ruler(axis=(0, 0, 1), kind='screen', step=40)
shot("Z-extrude ruler rendered — pick tick from _exmap.png")

# Action N+1: apply
T = 0.18   # world-space distance, read from e3 tick in the PNG
bpy.ops.mesh.extrude_region_move(
    TRANSFORM_OT_translate={"value": (0, 0, T), "orient_type": "GLOBAL"}
)
shot(f"extruded {T}m along Z")
```

## O9–O11 — Modifiers (set directly, no overlay)

Modifiers do not have overlay wrappers — parameters are set by direct API calls.
Apply them in OBJECT mode.

```python
bpy.ops.object.mode_set(mode='OBJECT')
obj = bpy.context.active_object

# Mirror across X and Y
mir = obj.modifiers.new("Mirror_XY", 'MIRROR')
mir.use_axis[0] = True   # X
mir.use_axis[1] = True   # Y
mir.use_axis[2] = False  # Z

# Bevel (edge-width)
bev = obj.modifiers.new("Bevel", 'BEVEL')
bev.width    = 0.003
bev.segments = 3

# Subdivision surface
sub = obj.modifiers.new("Subsurf", 'SUBSURF')
sub.levels         = 2
sub.render_levels  = 2

# Apply a modifier permanently (fuses it into the mesh)
bpy.ops.object.modifier_apply(modifier="Mirror_XY")

# Other available modifier types (no helpers, set params directly):
# SOLIDIFY, ARRAY, SCREW, BOOLEAN
```

## lib/mesh.py — BMesh utilities (used inside operation actions)

These are lower-level helpers used within operation actions. You do not need an
overlay for them — they operate directly on BMesh.

| Function | What it does |
|---|---|
| `walk_ring(edge)` | Returns all edges in the loop-cut ring through `edge` |
| `loopcut_at_fractions(obj, bm, ring_edges, fractions, top_z, bottom_z, from_top=True)` | Cuts `len(fractions)` new rings into `ring_edges`, each at an arbitrary fraction of the `[bottom_z, top_z]` span instead of `subdivide_edges`'s even spacing |
| `selected_verts_world(bm, mw)` | World coords of all currently selected verts |
| `centroid(points)` | Average of a list of world Vectors |
| `deselect_all(bm)` | Deselects all verts/edges/faces and flushes |
| `select_verts_at_z(bm, mw, z_list)` | Selects verts at given world-Z values |
| `z_levels(bm, mw)` | Sorted list of all unique world-Z values in the mesh |
| `GeoHistory` | Snapshot vert world positions before an op; query change after |


Worked examples, and `loopcut_at_fractions` for rings that must NOT be evenly
spaced: **`Tool_scripts/Tools_ref/operations.md`**.
